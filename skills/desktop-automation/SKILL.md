# desktop-automation

## 目标

在桌面图形界面中完成通用 GUI 操作：找到目标、执行动作、验证结果，
并在无法推进时明确汇报，而不是盲目点击。

## 前置条件

- 已知任务目标（要打开的应用、要点击的按钮文字、要填写的内容）；
- 每一步执行后都会收到新的屏幕信息（截图或 OCR 文本转写）。

## 通用工作流

1. **观察**：先读当前屏幕。若看不清或信息不足，调用 `screenshot` 获取
   最新画面；不确定界面状态时先 `wait`（0.5~2 秒）等界面加载。
   多步骤任务先调用 `plan` 记录目标与步骤，再逐步执行。
2. **定位目标**：
   - 若屏幕文本转写里能找到目标文字，用它旁边的归一化坐标 `[x,y]`
     调用 `click`；
   - 若需要打开应用，Linux 下按 `key_press` 组合键 `super` 呼出启动器，
     再 `type_text` 输入应用名并按 `enter`；
   - 找不到时滚动 `scroll` 或换一种方式搜索，不要在同一位置重复点击。
3. **执行动作**：
   - 单击 `click`、双击 `double_click`、右键 `right_click`；
   - 文本框先 `click` 聚焦，再 `type_text` 输入；
   - 下拉/滑块用 `scroll` 或 `drag` 拖动；
   - 快捷键用 `key_press`（如 `ctrl+s`、`alt+f4`、`enter`、`esc`）。
4. **验证**：动作后观察新屏幕，确认目标已变化（弹窗出现、文字改变等）；
   打开窗口/应用后用 `window_info` 确认焦点，再 `screenshot` 看内容。
   一次没生效就 `wait` 后重试一次，再失败就换方法。
5. **收尾**：完成后调用 `finish`，summary 说明实际完成的操作与验证结果；
   无法完成时也调用 `finish` 说明卡在哪一步、尝试过什么。

## 验收标准

- 每一步动作都有对应的屏幕观察依据，不凭猜测连续点击；
- 目标状态变化有截图/OCR 证据；
- 任务完成或失败都通过 `finish` 明确收尾。

## 注意事项

- 坐标是相对整张截图的归一化值 (0~1)，不要用像素；
- 中文 IME 输入不可靠，优先英文；必须输入中文时先尝试剪贴板方案；
- 打开浏览器/网址/新标签页用 `browser` 工具，不要手动点浏览器图标；
- 只执行任务范围内的操作，不打开无关窗口。
