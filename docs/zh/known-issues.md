# 已知问题与功能边界（代码现状评审）

> [返回索引](index.md) · [项目简介](../../README.zh.md)

本文基于 2026-09 的代码现状评审，按功能域整理当前实现中存在的问题与限制，
作为开发排期、路线图以及“隐私遮罩 / 动作预览 / 撤销 / 会话回放”等规划的输入。
[development.md](development.md) 的“已知限制”是简版；本页按域展开，条目只描述现状，
不承诺修复时间。完整设计与路线图见 [DESIGN.md](../DESIGN.md)。

## 平台与桌面环境

- 完整键鼠 + 可见终端 + 语义定位闭环目前只有 Linux X11；
  Windows/macOS 只是 pyautogui 与浏览器/终端“开窗”层面的尽力而为，
  Wayland 不支持；移动窗口、DPI/缩放、会话差异可能让坐标失效。
- 只抓取并操作第一块物理屏（`mss.monitors[1]`），坐标按主屏归一化；
  第二块屏幕上的目标既看不到也无法定位。
- 没有 `window_activate` / `app_launch` 这类确定性工具：Agent 无法直接唤醒、
  置顶或聚焦某个最小化/后台窗口，只能通过启动器、点击或键盘猜测；
  系统托盘、自启动常驻应用尤其不可靠。
- `window_info` 只读窗口列表与活动状态，不提供“激活窗口/切换焦点”动作；
  Electron、自绘应用或未暴露 AT-SPI 的窗口可能查不到标题与控件。
- 手机经局域网 HTTP 访问时 Web Speech API 与 Service Worker 不可用：
  语音自动走录音上传，PWA 退化为普通网页。

## 感知与状态验证

- Agent 的输入主要是整屏截图或 OCR 文本，没有 DOM、AT-SPI 控件树、
  布局/层级或窗口内结构的持续表示；模型多数时候在“看像素猜坐标”。
- `find_text` / `find_element` 只返回目标中心点，不返回可点击区域、
  控件状态或“对该控件可直接执行的动作”；无文字图标、图形按钮、
  Electron/自绘界面经常找不到。
- PaddleOCR 是远程 AI Studio 服务，单次识别最长约 90 秒；
  文本模式下每次“观察屏幕”都可能触发一次远程转写，长任务延迟和成本偏高；
  OCR 只能表达文字与包围盒，表达不了图标、颜色、层级和视觉布局。
- 前后帧差异是整屏 64×64 灰度比较，动作后固定等约 0.18 秒；
  没有区域断言、文本断言、窗口断言，动画、光标、加载态会造成误判，
  慢加载又容易判成“屏幕未变化”。
- 没有 `wait_until` / `assert` 类条件等待工具；`wait` 只是固定睡眠且单次上限
  10 秒，无法表达“等到标题出现”或“等到输入框可编辑”。
- 模型一次响应里调用多个工具时，工具会依次执行，但新的截图只在整批工具
  执行完后附加，批次中间无法插入新的观察；`screenshot` 工具本身不直接返回
  图片，实际由循环在整批之后补发，作为“批次中的即时观察”语义不成立。
- 上下文压缩达到阈值后会删除早期截图并用文本摘要替代，模型会失去部分
  早期视觉状态；摘要由模型生成，可能有信息损失。

## 键鼠动作粒度

- 只有离散动作：move/click/double_click/right_click/scroll/drag/type_text/
  key_press；没有 mouse_down/mouse_up、key_down/key_up、长按与按住移动，
  无法表达“按住期间连续反馈”的手势、选区、拖拽中的中间位置或绘图路径。
- `drag` 是一次性“从 A 拖到 B”，不是带中间轨迹的拖动；
  `scroll` 不接收目标坐标，若光标不在目标区域，滚动可能作用到错误窗口。
- 坐标全部是整屏归一化坐标，不是窗口相对坐标；
  目标窗口移动、缩放或切换后，模型记忆的坐标很容易失效。
- 中文等非 ASCII 文本走剪贴板粘贴，Linux 依赖 `xclip`/`xsel`；
  缺失时退回逐键输入，IME 支持差；剪贴板会被临时覆盖后恢复，仍可能干扰
  用户正在使用的剪贴板内容。
- Agent 没有独立的剪贴板读写工具，无法可靠地“复制一段屏幕文字再粘贴到
  另一处”；键盘输入没有键盘布局/本地化感知。

## 可见终端与浏览器

- 可见终端完整捕获只在 Linux + bash/常见终端组合下可靠；vi、htop、ssh 等
  交互式程序体验下降；命令输出等待默认 15 秒，长命令容易超时。
- macOS/Windows 上的 `open_terminal` 基本是“只开窗、不捕获输出”，
  `terminal_type/read/close` 会话语义只在 Linux 有效。
- 安全边界只审核 `open_terminal` 与 `terminal_type` 中命中黑名单/可执行输入；
  `key_press`、`type_text`、普通终端命令和手动直控不在审核范围，
  理论上仍可组合出未审核的危险操作。
- `browser` 只是确定性启动浏览器/打开 URL，没有 DOM/CDP/页面事件通道；
  后续的地址栏定位、搜索框聚焦、页面内容读取全部退回截图/OCR；
  macOS/Windows 的 `new_window` 语义是尽力而为，可能退化为新标签页。
- 除 `open_terminal` 外没有通用的文件读写工具；文件系统操作基本只能靠
  shell，Agent 没有“读文件/写文件/列目录”的结构化工具。

## 手动直控

- 触屏/虚拟触摸板只支持单指针的点击、双击、右键、拖拽与滚动；
  没有双指缩放、多点触控、笔触/压感，也没有“按住拖到动态目标”的中间态。
- 拖拽由“起点事件 + 终点事件”合成，不是完整轨迹；
  手动操作不会留下轨迹或回放数据，无法作为后续“教 Agent”的训练素材。
- 首个手动输入会把 Agent 标记为取消，但如果 Agent 正卡在人工审核等待中，
  手动输入并不会主动拒绝/解决该审核请求，需要再点停止或等待超时，
  “打断与接管”存在边界空隙。
- 手动直控绕过 Agent 步数与 shell 审核，且当前没有操作审计/录制；
  它代表用户本人操作，但误操作也没有撤销能力。

## 任务生命周期与智能闭环

- 前台一次只允许一个 Agent 任务；执行中再来命令会被拒绝为 busy，
  没有“暂停当前任务并插入新指令”的机制。
- `plan` 只是外置文本笔记，不是强约束状态机：模型可能跳过计划、不更新
  当前步骤，甚至“声称验证过”但没有证据；循环不会强制校验计划一致性。
- 没有检查点、持久化任务状态、恢复/继续执行能力，也没有等待人类完成
  “扫码登录/物理操作”的 `human_checkpoint` 语义；
  Agent 单任务默认 30 步上限，等待类操作会消耗步数。
- 没有撤销/回滚；上下文压缩、失败换方法等都不会保存可复现的动作历史，
  任务结束后只有轻量 trace 供进化使用，没有面向用户的可审计回放。
- 后台任务彼此独立，没有共享计划、协调层或结果合并；多个 Agent 并发时
  只通过全局输入锁串行键鼠，前台/后台都可能同时发起人工审核，
  而审核协议当前不携带 `task_id`，手机端难以区分请求来自哪个任务。

## 信任层（动作预览与隐私遮罩）

- 预览的“可视化延迟”只是让用户看得见并可拦截，不是强一致的事务边界；
  设成 0 或切到“全部放行”后就没有确认环节（终端黑名单审核仍然生效）。
- 需要确认的动作在无手机控制端在线时会被直接拒绝；后台/定时任务如需无人值守，
  应切到“全部放行”或保持手机端在线。
- 隐私遮罩只对主屏截图生效，不阻止点击；多显示器、子窗口与视频内容不做特殊
  处理，关闭总开关后不会打码。
- 自动识别只在点击时运行一次，依赖 AT-SPI 密码框与 OCR 关键词；自绘界面、
  未配置 OCR Token 或关键词未命中时会漏检，只作为建议，不保证覆盖全部敏感区域。
- 本阶段没有撤销与会话回放；`action_proposal.undoable` 恒为 false。

## 记忆、RAG、SKILL 与进化

- 持久记忆是“key-value + 关键词检索”，没有语义/向量检索、过期策略、
  权限隔离或加密；条目上限约 200 条、单条最长约 8000 字符，
  且提示注入防御只是关键词启发式。
- RAG 只锁定本地文件/文件夹与内置后缀白名单，不监听文件实时变化，
  需要重新 `add`/reindex 才对账；没有 URL/网页/数据库等数据源。
- SKILL 只是 Markdown 指引，没有可执行脚本、沙箱、dry-run 或自动验收；
  `read_skill` 只能读已扫描技能目录，不提供任意文件读取。
- 空闲进化与 POT 反思会在后台调用模型并把记忆、任务历史发给模型服务商；
  生成的 SKILL/ROT 不做回放验证，可能存在重复、低质量或指令注入内容，
  只有简单短语拦截。

## MCP

- MCP 工具没有空间/屏幕语义，无法参与“目标坐标”类预览与修正，
  当前设计只能显示通用参数摘要卡。
- 启用后的 MCP 工具视为用户已授权，不做逐次调用审批；stdio 服务器本质是
  在电脑上执行任意命令，导入即信任，安全边界不覆盖 MCP 工具返回后的副作用。
- MCP 工具调用单次超时约 30 秒；图片、资源引用等非文本内容会被丢弃，
  模型只能看到文本化结果。

## 安全、隐私与审计

- 扫码配对使用短期一次性配对码（默认 300 秒）换取 Token，配对码过期或已使用
  后需重新用 `--qr` 启动或手动输入 Token；服务端不提供运行中重新生成入口。
- 局域网 HTTP 下配对码与 Token 都可能被同网段嗅探，公众网络请使用
  Tailscale/HTTPS；Token 存在 `sessionStorage`，关闭标签页即清除，但页面若被
  XSS 注入仍可能读取。
- 默认服务监听 HTTP 局域网端口，没有内置 TLS；截图会发送给配置的模型
  服务商，启用 OCR 时还会上传到 AI Studio，当前没有本地 OCR 或敏感区域
  打码/脱敏能力。
- 当前没有会话录制、操作日志持久化或审计回放；谁在何时批准了什么动作、
  实际执行了什么参数，只在 WebSocket 事件里短暂存在，重启即丢失。
- 安全审核可以被配置关闭；自定义黑名单会整体替换内置规则，配置不当时
  防护范围小于默认值；审核超时默认 30 秒后自动拒绝。
- 手机端 Token 不落 localStorage，刷新后需要重新输入，安全性好但便利性差；
  WebSocket Token 通过子协议传递，REST 通过请求头，避免进入 URL，但仍依赖
  所在网络与隧道本身的传输安全。

## 测试与验收的盲区

- 自动化测试以 mock OpenAI + fake InputBackend 为主，覆盖逻辑层充分，
  但对真实桌面、真实微信/Electron/网页的端到端成功率没有量化基准。
- 没有“任务级成功断言”数据集（如打开微信→找到某人→发送→验证气泡），
  也没有回放/回归框架，因此“某个改动让真实任务更准还是更差”无法被测试
  捕捉。

以上条目是后续“精确性基础”（窗口激活、语义目标、条件等待、人工检查点、
应用配方）与“信任三件套”规划需要回填的现状缺口。
